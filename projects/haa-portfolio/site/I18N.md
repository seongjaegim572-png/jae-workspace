# HAA 포트폴리오 번역 관리

영어 원문은 `locales/en.json` 한곳에서 관리합니다. 한국어는 `locales/ko.json`이며 스페인어, 일본어, 중국어 파일도 같은 키를 사용합니다. 현재 화면과 기능은 유지하면서, 화면 문구·메뉴 안내·접근성 설명·Sibyl 결과 문구를 같은 리소스에 모았습니다.

## 문구 하나 수정하기

예를 들어 메뉴의 영어 `Work`를 바꿀 때에는 다음 명령만 사용합니다.

```sh
node scripts/i18n.mjs set en nav.work "Selected work"
node scripts/i18n.mjs status
```

상태 목록에는 수정된 `nav.work`만 갱신 대상으로 나타납니다. 한국어는 해당 키만 수정하면 됩니다.

```sh
node scripts/i18n.mjs set ko nav.work "주요 작업"
```

번역 문구를 그대로 써도 되는 경우에는 내용을 확인한 뒤 그 키만 현재 원문과 동기화할 수 있습니다.

```sh
node scripts/i18n.mjs accept ko nav.work
```

아직 갱신하지 않은 번역이나 누락된 키는 영어로 표시됩니다. 기존 번역은 원본 파일에 남아 있습니다. 상태를 표시하는 기준은 원문의 변경 이력이며, 번역의 언어적 정확성까지 자동으로 보장하는 것은 아닙니다.

## 관리 위치

- `locales/en.json`: 원본 영어 문구. 문구가 바뀌어도 기존 키 이름은 유지합니다.
- `locales/ko.json`: 보조 언어인 한국어.
- `locales/es.json`, `ja.json`, `zh.json`: 기존 추가 언어.
- `src/pages/`: 문구 대신 번역 키를 참조하는 페이지 템플릿. 구조 변경은 여기서 합니다.
- `.i18n/state.json`: 각 번역이 어느 영어 원문과 동기화되었는지 기록.
- `i18n.config.json`: 원본·보조 언어, 저장 키, 언어 목록.
- `dist/`: 게시용 결과. 이곳의 생성된 HTML, 번역 파일, `i18n-source.js`를 직접 수정하지 않습니다.

번역 파일 안의 `span`, `em`, `strong` 등 서식 태그와 `{name}`, `{goal}` 등의 자리표시자는 유지합니다. 브랜드 이름과 언어 선택 버튼의 고유 언어명도 유지합니다.

## 검증과 생성

```sh
node scripts/i18n.mjs build
node scripts/i18n.mjs check
node tests/i18n-runtime.test.cjs
node tests/i18n-workflow.test.mjs
```

생성 시 영어 원문으로 모든 페이지의 기본 내용을 채우므로 JavaScript가 꺼져도 영어 본문을 읽을 수 있습니다. 변경 내용으로 캐시 버전을 계산하여 이전 번역이 남는 문제도 줄였습니다. 언어 선택 저장과 기본 언어 감지, 독립적인 테마 스위치는 기존 방식대로 동작합니다.

## Tolgee를 추후 연결하기

지금은 외부 계정이나 API 키 없이 작동하는 가벼운 JSON 시스템입니다. 자동 번역 서비스는 아직 연결하지 않았습니다.

Tolgee는 JSON 파일의 가져오기·내보내기와 CLI 동기화를 지원합니다. 현재의 동일한 키를 그대로 사용할 수 있습니다.

1. Tolgee에서 영어를 기준 언어로 프로젝트를 만들고, 현재 언어 파일을 가져옵니다.
2. `.tolgeerc.example.json`을 `.tolgeerc`로 복사하고 실제 프로젝트 ID를 설정합니다.
3. API 키는 공개 파일에 넣지 않고 `TOLGEE_API_KEY` 환경 변수로 전달합니다.
4. 영어를 업로드하고 번역을 받은 뒤 현재 시스템으로 가져옵니다.

```sh
node scripts/i18n.mjs export ./translation-export
# Tolgee CLI를 별도로 설치하고 계정을 연결한 후:
tolgee push --languages en
tolgee pull
node scripts/i18n.mjs import ko ./translation-import/ko.json ./translation-export/source-fingerprints.json
```

영어가 업로드 이후 다시 바뀐 키는 가져오기에서 건너뛰어 오래된 원문에 대한 번역이 덮어쓰지 않게 합니다. JSON을 중첩 구조로 받아도 가져올 수 있습니다. 플랫폼을 바꾸더라도 페이지 키를 다시 만들 필요가 없습니다.

공개된 번역 JSON 주소나 SDK를 쓰고 싶을 때는 `window.portfolioI18n.setLoader()` 또는 `registerTranslations()`를 연결할 수 있습니다. API 키를 브라우저에 노출하는 방식은 사용하지 않습니다. 게시용 파일로 가져오는 위의 방식이 기본 경로입니다.
